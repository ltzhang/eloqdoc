## Summary of 6.0 Changes (Data Model Focus)

| Area | Change |
|---|---|
| **Indexes** | New `2dsphere_bucket` index type; compound wildcard indexes |
| **Collection types** | Clustered collections GA; encrypted field collections (FLE2) |
| **Aggregation** | New `$densify`, `$fill` stages; new accumulators (`$locf`, topN/bottomN) |
| **Change streams** | Pre/post-image support; `$changeStreamSplitLargeEvent` |
| **FLE2** | Queryable Encryption (client-side); `compactStructuredEncryptionData` command |
| **`create` command** | `encryptedFields`, `changeStreamPreAndPostImages`, `clusteredIndex` fields |
| **Time-series** | Secondary indexes; geospatial on time-series |
| **Column store index** | Experimental (preview) in 6.0 |
| **Query optimizer** | Cascades Query Framework (CQF) introduced (not user-configurable yet) |

## 1. Index Types — Changes in 6.0

### 1.1 New: `2dsphere_bucket` Index

**Added in 6.0** for indexing geospatial data in time-series collections.

`src/mongo/db/index_names.h`:
```cpp
INDEX_2DSPHERE_BUCKET,   // "2dsphere_bucket"
IndexNames::GEO_2DSPHERE_BUCKET = "2dsphere_bucket";
```

**Purpose:** Enables geospatial queries on time-series collections. The bucket storage format requires a special index type that understands the bucketed geometry.

**Key pattern:** `{ geoField: "2dsphere" }` on a time-series collection — the server internally creates a `2dsphere_bucket` index on the underlying `system.buckets.*` collection.

**User creation:** Users create a standard `"2dsphere"` index on a time-series collection; MongoDB automatically uses `"2dsphere_bucket"` internally.

### 1.2 Compound Wildcard Indexes

**Added in 6.0 (as experimental; GA in 7.0).** Wildcard indexes can now be combined with other fields in a compound index:

```js
db.collection.createIndex({ "$**": 1, category: 1 })   // wildcard + regular
db.collection.createIndex({ "a.$**": 1, b: -1 })       // sub-path wildcard + regular
```

**Restrictions:**
- At most one wildcard field per compound index.
- Wildcard field cannot be the second field in the compound if used for sorting.
- `wildcardProjection` still applies to the wildcard field.

### 1.3 Column Store Index (Experimental Preview)

**Added as experimental in 6.0.** Column store indexes store each field's values separately (columnar layout), enabling efficient scans of a subset of fields without reading entire documents.

`src/mongo/db/index_names.h`: `INDEX_COLUMN` with string `"columnstore"`.

**Key pattern:**
```js
{ "$**": "columnstore" }   // index all fields in columnar format
```

**Restrictions in 6.0:**
- Cannot be combined with other index types.
- Not recommended for production use in 6.0 (experimental).
- Does not support all query patterns in 6.0.

**Became stable in 7.0** (but then deprecated in 8.0).

## 2. Clustered Collections — GA in 6.0

**Introduced as preview in 5.3; GA in 6.0.** Clustered collections store documents physically sorted by the cluster key, improving range scans on that key.

### 2.1 Creating a Clustered Collection

```js
db.createCollection("<name>", {
  clusteredIndex: {
    key: { _id: 1 },     // must be _id for user collections
    unique: true,        // must be true
    name: "<name>"       // optional; defaults to auto-generated
  }
})
```

Short form (for _id clustering):
```js
db.createCollection("<name>", { clusteredIndex: true })
```

**`ClusteredIndexSpec` IDL fields** (from `src/mongo/db/catalog/clustered_collection_options.idl`):

| Field | Type | Default | Notes |
|---|---|---|---|
| `v` | int | 2 | Index format version |
| `key` | object | required | The cluster key; must be `{ _id: 1 }` for user collections |
| `name` | string | optional | Index name |
| `unique` | safeBool | true | Must be true |

**`ClusteredCollectionInfo` IDL fields:**

| Field | Type | Notes |
|---|---|---|
| `indexSpec` | ClusteredIndexSpec | The cluster key specification |
| `legacyFormat` | safeBool | Internal: used for system collections (e.g., `system.buckets.*`) |

### 2.2 Benefits and Restrictions

**Benefits:**
- Range queries on `_id` are much faster (no need to follow index pointers).
- Time-series system bucket collections use `_id` clustering internally.
- Eliminates the overhead of a separate `_id` index (there is no separate `_id` index).

**Restrictions:**
- Cannot have a separate `_id` index (the clustered index IS the _id index).
- `_id` is the only supported cluster key for user-created clustered collections in 6.0 (arbitrary cluster keys were added in 7.0 for internal use).
- Once clustered, cannot be converted to non-clustered without recreating.
- `expireAfterSeconds` on a clustered collection creates a TTL based on `_id` (must be an ObjectId or Date).

## 3. Queryable Encryption / FLE2

**New in 6.0.** FLE2 (Field Level Encryption 2) is a significant upgrade from the CSFLE introduced in 4.2. Unlike CSFLE, FLE2 (also marketed as "Queryable Encryption") allows the server to execute **equality queries** on encrypted fields **without decrypting them**.

### 3.1 Architecture

- **Client:** Encrypts field values using the libmongocrypt library.
- **Server:** Stores encrypted values in specialized internal collections. For equality queries, maintains encrypted state collections (ESC, ECC, ECOC) alongside the main collection.
- **Encrypted BSON subtype:** Still uses BinData subtype 6 for the encrypted payload.

### 3.2 `encryptedFields` in `create` Command

**New field in `create` command** (from `create.idl` in v6.0):
```js
db.createCollection("<name>", {
  encryptedFields: {
    keyId: UUID("..."),         // optional; can be at field level
    fields: [
      {
        keyId: UUID("..."),     // key for this field
        path: "ssn",            // dot-notation path
        bsonType: "string",
        queries: [{ queryType: "equality" }]  // enable encrypted equality queries
      },
      {
        keyId: UUID("..."),
        path: "salary",
        bsonType: "double",
        queries: [{ queryType: "rangePreview", min: 0, max: 1000000, precision: 2, sparsity: 1 }]
      }
    ]
  }
})
```

**`EncryptedFieldConfig` fields:**

| Field | Type | Notes |
|---|---|---|
| `keyId` | UUID | Default encryption key |
| `fields` | array of EncryptedField | Per-field encryption specifications |

**Per-`EncryptedField` fields:**

| Field | Type | Notes |
|---|---|---|
| `keyId` | UUID | Encryption key for this field |
| `path` | string | Dot-notation field path |
| `bsonType` | string | BSON type of the plaintext value |
| `queries` | array of QueryTypeConfig | Query types enabled on this field |

**`QueryTypeConfig` fields:**

| Field | Type | Notes |
|---|---|---|
| `queryType` | string | `"equality"` or `"rangePreview"` |
| `min` | value | Range minimum (rangePreview only) |
| `max` | value | Range maximum (rangePreview only) |
| `precision` | int | Decimal places for range (rangePreview only) |
| `sparsity` | int | Index sparsity for range (rangePreview only) |

### 3.3 `compactStructuredEncryptionData` Command

**New in 6.0.** Compacts the internal FLE2 state collections (ESC, ECC, ECOC) to reclaim space:

```js
db.runCommand({
  compactStructuredEncryptionData: "<collection>",
  compactionTokens: { <field>: BinData(...), ... }
})
```

**Source:** `src/mongo/db/commands/fle2_compact_cmd.cpp`

### 3.4 FLE2 CRUD Operations

**Source:** `src/mongo/db/fle_crud.cpp`

When a collection has `encryptedFields`:
- **Inserts** validate that encrypted fields are present as BinData subtype 6.
- **Updates** on encrypted fields require the client to re-encrypt.
- **Deletes** clean up ESC/ECC entries.
- **Equality queries** on encrypted fields are transparently rewritten by the server to use the encrypted state collections.

**Query rewriting source:** `src/mongo/db/query/fle/server_rewrite.cpp`

## 4. Aggregation Pipeline — Changes in 6.0

### 4.1 New Stage: `$densify`

**Source:** `src/mongo/db/pipeline/document_source_densify.cpp`  
**IDL:** `src/mongo/db/pipeline/document_source_densify.idl`

Generates new documents to fill gaps in a sequence of numeric or date values.

```js
{ $densify: {
    field: "<fieldName>",
    partitionByFields: ["<field>", ...],    // optional
    range: {
      step: <number>,
      unit: "millisecond" | "second" | "minute" | "hour" | "day" | "week" | "month" | "quarter" | "year",  // for dates
      bounds: "full" | "partition" | [<lower>, <upper>]
    }
}}
```

**`range.bounds` values:**
| Value | Description |
|---|---|
| `"full"` | Fill gaps across the entire range of values in the dataset |
| `"partition"` | Fill gaps within each partition (requires `partitionByFields`) |
| `[lower, upper]` | Fill between explicit bounds (always generates all values in range) |

**Use case:** Time-series visualization — ensure every time slot has a document even if no data was recorded.

### 4.2 New Stage: `$fill`

**Source:** `src/mongo/db/pipeline/document_source_fill.cpp`  
**IDL:** `src/mongo/db/pipeline/document_source_fill.idl`

Fills `null` or missing values in a sequence of documents.

```js
{ $fill: {
    partitionBy: <expression>,             // optional; group by field
    partitionByFields: ["<field>", ...],   // alternative to partitionBy
    sortBy: { field: 1 | -1 },            // required for locf/linear
    output: {
      <fieldName>: {
        method: "locf" | "linear"          // OR
        value: <constant expression>
      }
    }
}}
```

**Fill methods:**
| Method | Description | Source |
|---|---|---|
| `"locf"` | Last observation carried forward: fills with the most recent non-null value | `accumulator_locf.cpp` |
| `"linear"` | Linear interpolation between known values | (computed in fill stage) |
| `value` | Fill with a constant expression | — |

### 4.3 New Accumulators

#### `$locf` (Last Observation Carried Forward)

**Source:** `src/mongo/db/pipeline/accumulator_locf.cpp`

```js
{ $setWindowFields: {
    sortBy: { date: 1 },
    output: {
      filledValue: {
        $locf: "$value",
        window: { documents: ["unbounded", "current"] }
      }
    }
}}
```

#### TopN / BottomN Accumulators

**Source:** `src/mongo/db/pipeline/accumulator_multi.cpp`

New accumulators that return multiple values:

| Accumulator | Description |
|---|---|
| `$minN` | Returns the N smallest values |
| `$maxN` | Returns the N largest values |
| `$firstN` | Returns the first N values (by sort order) |
| `$lastN` | Returns the last N values (by sort order) |
| `$topN` | Returns the top N documents by a sort |
| `$bottomN` | Returns the bottom N documents by a sort |
| `$top` | Returns the top document by a sort |
| `$bottom` | Returns the bottom document by a sort |

**Syntax:**
```js
{ $group: {
    _id: "$category",
    topSellers: {
      $topN: {
        n: 3,
        sortBy: { sales: -1 },
        output: "$name"       // field to return
      }
    }
}}
```

### 4.4 New Stage: `$listCatalog`

```js
db.aggregate([{ $listCatalog: {} }])
```

Returns information about all collections and views in the database (or deployment). Fields: `ns`, `type`, `options`, `info`, `idIndex`.

### 4.5 New Stage: `$shardedDataDistribution`

```js
db.aggregate([{ $shardedDataDistribution: {} }])
```

Returns chunk distribution info across shards. (Cluster-level admin query; sharding-related but user-visible.)

### 4.6 New Stage: `$setVariableFromSubPipeline`

**Source:** `src/mongo/db/pipeline/document_source_set_variable_from_subpipeline.cpp`

Internal stage used to assign the result of a sub-pipeline to a variable. Used internally in `$lookup` and `$graphLookup` optimization.

### 4.7 Change Streams: Pre/Post-Image Support

**New in 6.0.** Change stream events can now include the full pre- and post-modification document.

**Collection-level enablement** (new `create` command option):
```js
db.createCollection("<name>", {
  changeStreamPreAndPostImages: { enabled: true }
})
```

Or via `collMod`:
```js
db.runCommand({
  collMod: "<collection>",
  changeStreamPreAndPostImages: { enabled: true }
})
```

**Watch with pre/post images:**
```js
db.collection.watch([], {
  fullDocument: "required" | "whenAvailable" | "updateLookup",
  fullDocumentBeforeChange: "required" | "whenAvailable" | "off"
})
```

**`$changeStream` stage options (updated):**
```js
{ $changeStream: {
    fullDocument: "default" | "updateLookup" | "required" | "whenAvailable",
    fullDocumentBeforeChange: "off" | "required" | "whenAvailable",
    resumeAfter: <resumeToken>,
    startAfter: <resumeToken>,
    startAtOperationTime: <Timestamp>,
    allChangesForCluster: bool,
    showExpandedEvents: bool  // new in 6.0: show DDL events
}}
```

### 4.8 New Internal Change Stream Stages

In 6.0 the change stream infrastructure is refactored into distinct stages (all internal, not user-accessible):
- `$_internalChangeStreamAddPostImage`
- `$_internalChangeStreamAddPreImage`
- `$_internalChangeStreamCheckInvalidate`
- `$_internalChangeStreamCheckResumability`
- `$_internalChangeStreamCheckTopologyChange`
- `$_internalChangeStreamHandleTopologyChange`
- `$_internalChangeStreamOplogMatch`
- `$_internalChangeStreamSplitLargeEvent`
- `$_internalChangeStreamTransform`
- `$_internalChangeStreamUnwindTransaction`

### 4.9 New Stage: `$changeStreamSplitLargeEvent`

User-accessible stage for splitting change stream events that exceed the 16MB BSON limit:

```js
db.collection.watch([{ $changeStreamSplitLargeEvent: {} }])
```

Must be the last stage in the change stream pipeline.

### 4.10 New Stage: `$queryStats` (Internal)

```js
db.aggregate([{ $queryStats: {} }])
```

Returns query statistics (query shape, execution counts, latencies) collected by the query stats system. The collected data helps identify slow or frequently executed queries. New in 6.0.

## 7. Time-Series Enhancements in 6.0

### 7.1 Secondary Indexes on Time-Series

In 6.0, secondary indexes on time-series collections are fully supported:
```js
db.temps.createIndex({ location: 1, timestamp: 1 })  // secondary on metaField + timeField
db.temps.createIndex({ "sensors.value": 1 })          // secondary on measurement field
```

### 7.2 Geospatial Indexes on Time-Series

Using `"2dsphere"` on a time-series collection now works correctly (internally creates `2dsphere_bucket`):
```js
db.gpsReadings.createIndex({ "location": "2dsphere" })
```

### 7.3 Time-Series Updates and Deletes (Partial)

In 6.0, updates and deletes on time-series are supported with restrictions:
- **Updates:** Only on `metaField` sub-fields; cannot update `timeField`.
- **Deletes:** Supported but not yet optimized (rewrites entire bucket).

## 9. Feature Compatibility Version in 6.0

```js
db.adminCommand({ setFeatureCompatibilityVersion: "6.0" | "5.0" })
```

Setting to "6.0" enables:
- `$densify` and `$fill` stages
- FLE2 / Queryable Encryption
- Clustered collections
- Pre/post-image change streams
- Compound wildcard indexes (experimental)
- Column store indexes (experimental)

## 10. Breaking Changes from 5.0 → 6.0

1. **`reIndex` command removed:** Use `dropIndexes` + `createIndexes` instead.
2. **MapReduce `out: { inline: 1 }` changes:** Now emits deprecation warning with suggestion to use aggregation.
3. **Change stream internal stage refactoring:** Old internal stages (`document_source_check_invalidate`, `document_source_check_resume_token`, `document_source_lookup_change_pre_image`, `document_source_lookup_change_post_image`) are replaced by new ones. Resume tokens may not be compatible across this version boundary.
4. **`$out` on views:** No longer allowed.
5. **`$group` with `$sum` on missing fields:** Now consistently returns 0 instead of null.
