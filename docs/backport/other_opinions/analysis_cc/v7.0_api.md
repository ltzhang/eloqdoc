## Summary of 7.0 Changes (Data Model Focus)

| Area | Change |
|---|---|
| **Indexes** | `INDEX_COLUMN` (columnstore) becomes stable; `INDEX_ENCRYPTED_RANGE` added |
| **FLE2** | Range queries on encrypted fields (rangePreview → range); `getFLECount` command |
| **Aggregation** | New `$percentile` and `$median` accumulators |
| **Analytics** | `$listSampledQueries` stage |
| **Bulk write** | `bulkWrite` command promoted as first-class command |
| **Time-series** | Bucket catalog refactored; arbitrary cluster key enabled internally |
| **Compound wildcard** | GA (no longer experimental) |

## 1. Index Types — Changes in 7.0

### 1.1 `INDEX_COLUMN` (Column Store Index) — Stable

**Promoted from experimental to stable in 7.0.** The `"columnstore"` index type is now production-ready.

`src/mongo/db/index_names.h` in v7.0:
```cpp
enum IndexType {
    INDEX_BTREE,
    INDEX_COLUMN,          // "columnstore" — stable in 7.0
    INDEX_2D,
    INDEX_ENCRYPTED_RANGE, // NEW in 7.0
    INDEX_HAYSTACK,
    INDEX_2DSPHERE,
    INDEX_2DSPHERE_BUCKET,
    INDEX_TEXT,
    INDEX_HASHED,
    INDEX_WILDCARD,
};
```

**Column store index creation:**
```js
db.collection.createIndex({ "$**": "columnstore" })
```

**How it works:** Instead of storing one entry per document with all indexed field values (row-oriented like btree), a columnstore index stores one column per field with all documents' values for that field. This enables:
- Efficient scans reading only a subset of fields
- Better compression (similar values in a column compress well)
- Faster aggregation queries that touch many documents but few fields

**Query compatibility:**
- Equality: `{ field: value }`
- Range: `{ field: { $gt: 5 } }`
- Compound path access: `{ "a.b": value }`
- Not suitable for multi-key (array) fields

**Restrictions:**
- One columnstore index per collection.
- Cannot be sparse, unique, TTL, or partial.
- Cannot be combined with other index types in a compound.

### 1.2 `INDEX_ENCRYPTED_RANGE` — New in 7.0

**Added in 7.0** to support FLE2 range queries on encrypted fields.

`IndexNames::ENCRYPTED_RANGE = "queryable_encrypted_range"` (internal; not user-created directly).

This is a virtual/pseudo-index type — it represents the internal index structure used by the FLE2 engine to enable range queries on encrypted data. Users do not create it directly; it is created implicitly when a field with `queries: [{ queryType: "range" }]` is specified in `encryptedFields`.

## 2. FLE2 Enhancements in 7.0

### 2.1 Range Queries on Encrypted Fields (GA)

**Range queries** on FLE2-encrypted fields transition from `"rangePreview"` (6.0) to `"range"` (7.0):

**In 6.0:** `queries: [{ queryType: "rangePreview", ... }]`  
**In 7.0:** `queries: [{ queryType: "range", ... }]`

Range query configuration:
```js
db.createCollection("salaries", {
  encryptedFields: {
    fields: [{
      keyId: UUID("..."),
      path: "salary",
      bsonType: "int",
      queries: [{
        queryType: "range",
        min: 0,
        max: 200000,
        sparsity: 1,
        precision: 0     // integer precision
      }]
    }]
  }
})
```

**Supported types for range encryption:**
- `int`, `long`, `double`, `decimal`, `date`

**`range` query config fields:**

| Field | Type | Required | Notes |
|---|---|---|---|
| `queryType` | string | yes | `"range"` |
| `min` | value | yes | Minimum value of the range |
| `max` | value | yes | Maximum value of the range |
| `sparsity` | int | yes | Controls index density (1 = dense; higher = sparser) |
| `precision` | int | no | Decimal places for double/decimal types |

**Supported encrypted range predicates:**
- `{ encField: { $lt: X } }`, `$lte`, `$gt`, `$gte`
- `{ encField: { $gt: X, $lt: Y } }` (bounded range)
- NOT supported: `$in`, `$nin`, `$eq` with range config (use equality config for `$eq`)

### 2.2 `getFLECount` Command

**New in 7.0.** Returns count information about FLE2 internal state collections:

```js
db.runCommand({ getFLECount: "<collection>" })
```

**Source:** `src/mongo/db/commands/fle2_get_count_info_command.cpp`  
**IDL:** `src/mongo/db/commands/fle2_get_count_info_command.idl`

Returns ESC (Encrypted State Collection) document counts, useful for monitoring FLE2 compaction needs.

### 2.3 FLE2 Query Rewriting Infrastructure

**Source:** `src/mongo/db/query/fle/`

Dedicated query rewriting module for FLE2:
- `server_rewrite.cpp` — entry point for query rewriting
- `query_rewriter.cpp` — core rewriting logic
- `encrypted_predicate.cpp` — abstract predicate rewriting
- `equality_predicate.cpp` — equality predicate rewriting
- `range_predicate.cpp` — range predicate rewriting
- `range_validator.cpp` — validates range query parameters

## 3. Aggregation Pipeline — Changes in 7.0

### 3.1 New Accumulators: `$percentile` and `$median`

**Source:** `src/mongo/db/pipeline/accumulator_percentile.cpp`

#### `$percentile`

Returns the value at a specified percentile in a dataset. Can be used in `$group` and `$setWindowFields`.

```js
{ $group: {
    _id: "$product",
    p50: {
      $percentile: {
        input: "$responseTime",
        p: [0.5],           // array of percentiles (0.0 to 1.0)
        method: "approximate"
      }
    },
    p90: {
      $percentile: {
        input: "$responseTime",
        p: [0.9],
        method: "approximate"
      }
    }
}}
```

**Fields:**

| Field | Type | Required | Notes |
|---|---|---|---|
| `input` | expression | yes | Numeric expression to compute percentile of |
| `p` | array of float | yes | Percentile values (0.0–1.0) |
| `method` | string | yes | `"approximate"` (t-digest algorithm) |

**Note:** Only `"approximate"` method is available; exact computation is not supported due to memory constraints.

#### `$median`

Shorthand for `$percentile` at p=0.5:

```js
{ $group: {
    _id: "$category",
    medianLatency: {
      $median: {
        input: "$latency",
        method: "approximate"
      }
    }
}}
```

Both `$percentile` and `$median` can be used:
- In `$group` as group accumulators
- In `$setWindowFields` as window function operators
- In `$project` and `$addFields` as array reduction operators (new behavior)

### 3.2 New Stage: `$listSampledQueries`

**Source:** `src/mongo/db/pipeline/document_source_list_sampled_queries.cpp`

Returns sampled queries from the query sampling system (used for auto-analyzing shard key candidates):

```js
db.aggregate([
  { $listSampledQueries: { namespace: "db.collection" } }
])
```

Outputs query shape, operation type, and sample metadata.

## 4. `bulkWrite` Command (Promoted in 7.0)

**Source:** `src/mongo/db/commands/bulk_write.cpp`

`bulkWrite` is a new top-level command (not to be confused with the `Bulk` API on the driver) that allows mixing insert, update, and delete operations across **multiple collections** in a single command:

```js
db.adminCommand({
  bulkWrite: 1,
  ops: [
    { insert: 0, document: { name: "Alice" } },
    { update: 1, filter: { _id: 1 }, updateMods: { $inc: { count: 1 } } },
    { delete: 0, filter: { status: "inactive" }, multi: false }
  ],
  nsInfo: [
    { ns: "mydb.users" },     // index 0
    { ns: "mydb.counters" }   // index 1
  ],
  ordered: true,
  bypassDocumentValidation: false,
  writeConcern: { w: "majority" }
})
```

**`nsInfo` element fields:**

| Field | Type | Notes |
|---|---|---|
| `ns` | string | Namespace (`db.collection`) |
| `collectionUUID` | UUID | optional; for UUID-locked operations |

**Operation fields:**

For insert ops: `{ insert: <nsIndex>, document: <doc> }`  
For update ops: `{ update: <nsIndex>, filter: <filter>, updateMods: <update|pipeline>, upsert: bool, multi: bool, hint: ..., collation: ..., arrayFilters: [...] }`  
For delete ops: `{ delete: <nsIndex>, filter: <filter>, multi: bool, hint: ..., collation: ... }`

**Key advantage:** Reduces round-trips for multi-collection batch operations. Useful for applications that need to atomically (within a session) operate on multiple collections.

## 5. Time-Series Enhancements in 7.0

### 5.1 Bucket Catalog Refactoring

The time-series bucket catalog is refactored into a `bucket_catalog/` subdirectory:
- `bucket_catalog.cpp/h` — main catalog logic
- `bucket_catalog_helpers.cpp/h` — helper functions
- `bucket_catalog_internal.cpp/h` — internal implementation
- `bucket_catalog_server_status.cpp/h` — monitoring
- `bucket_identifiers.cpp/h` — bucket ID handling
- `bucket_metadata.cpp/h` — bucket metadata management
- `bucket_state_registry.cpp/h` — state machine for bucket lifecycle

This is an internal refactoring; the external API for time-series collections is unchanged.

### 5.2 Extended Range Support

Time-series supports timestamps outside the "normal" range (1970–2038):
- `kUsesExtendedRange` flag in `$_internalUnpackBucket`
- Dates before 1970-01-01 and after 2038-01-19 are now fully supported

### 5.3 Sharded Time-Series (7.0)

Time-series collections can be sharded in 7.0. The shard key must be on the `metaField` or `timeField`. (Sharding-related, mentioned for completeness.)

## 6. Compound Wildcard Indexes — GA in 7.0

Compound wildcard indexes introduced experimentally in 6.0 are now **generally available** in 7.0.

**Example:**
```js
db.products.createIndex({ category: 1, "attributes.$**": 1 })
```

**Supported query patterns:**
- Equality on `category` + any field under `attributes`
- Range on `category` + equality on any field under `attributes`

## 7. `analyze` Command (Non-Sharding Use)

**Source:** `src/mongo/db/commands/analyze_cmd.cpp`

While primarily for shard key analysis, `analyze` can be used standalone to generate query statistics about a collection's field value distributions.

```js
db.runCommand({
  analyze: "<collection>",
  key: "<field>",
  keyCharacteristics: { ... }
})
```

## 8. `changeStreamState` Command

**New in 7.0.** Controls change stream behavior at the cluster level:

```js
db.adminCommand({
  setChangeStreamState: 1,
  enabled: true | false
})

db.adminCommand({ getChangeStreamState: 1 })
```

When disabled, all change streams on the cluster return an error.

## 10. Feature Compatibility Version in 7.0

```js
db.adminCommand({ setFeatureCompatibilityVersion: "7.0" | "6.0" })
```

Setting to "7.0" enables:
- Column store indexes (stable)
- `INDEX_ENCRYPTED_RANGE` for FLE2 range queries
- `$percentile` and `$median` accumulators
- `bulkWrite` command
- Compound wildcard indexes (GA)

## 11. Breaking Changes from 6.0 → 7.0

1. **FLE2 `rangePreview` renamed to `range`:** Any code specifying `queryType: "rangePreview"` must be updated to `queryType: "range"`.
2. **Column store index behavior changes:** Some query patterns that didn't use column store in 6.0 may now use it in 7.0; verify query plans.
3. **Time-series bucket format:** Internal bucket document format v2 introduced for compression improvements; transparent to users but bucket documents from 6.0 cannot be read by 5.0.
