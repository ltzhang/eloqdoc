# MongoDB 8.0 API Surface and 4.0 Backport Notes

## What Changed From 7.0

8.0 adds search/vector/search-index management, query settings, mature `bulkWrite` response fields, more bit/percentile expressions, and FLE cleanup improvements:

- Search index commands: `createSearchIndexes`, `dropSearchIndex`, `updateSearchIndex`, `listSearchIndexes`.
- Aggregation search stages: `$search`, `$searchBeta`, `$searchMeta`, `$vectorSearch`, `$listSearchIndexes`, and internal mongot remote/search id lookup stages.
- Query settings commands: `setQuerySettings`, `removeQuerySettings`; `find`, `aggregate`, and `distinct` can carry internal `querySettings`.
- `bulkWrite` adds stable field annotations, reply counters, `let`, and `errorsOnly`.
- FLE cleanup command `cleanupStructuredEncryptionData` appears; FLE compact adds `anchorPaddingFactor`, `validator`, `encryptionInformation`.
- Expressions add bit operators (`$bitAnd`, `$bitOr`, `$bitXor`, `$bitNot`) and approximate stats (`$median`, `$percentile`).
- `create` collection options include `recordIdsReplicated`; `createIndexes` index specs include `columnstoreProjection`, `columnstoreCompressor`, `clustered`, and `prepareUnique`.

## Data Command Surface

| Command/API | Source | Request shape |
| --- | --- | --- |
| `createSearchIndexes` | `src/mongo/db/commands/search_index_commands.idl` | Namespace + `indexes: [{name?, definition, type?}]`; requires `createSearchIndexes` action. |
| `dropSearchIndex` | same | Namespace + optional `name` or `id`; requires `dropSearchIndex`. |
| `updateSearchIndex` | same | Namespace + optional `name` or `id`, required `definition`; requires `updateSearchIndex`. |
| `listSearchIndexes` | same | Namespace + optional `name` or `id`; returns a cursor-like object. |
| `setQuerySettings` | `src/mongo/db/commands/query_settings_cmds.idl`, `src/mongo/db/query/query_settings/*` | Query instance or shape hash plus settings such as allowed indexes or reject. |
| `removeQuerySettings` | same | Query instance or shape hash. |
| `bulkWrite` | `src/mongo/db/commands/bulk_write.idl` | Adds `let`, `errorsOnly`, reply counters (`nInserted`, `nMatched`, `nModified`, `nUpserted`, `nDeleted`, `nErrors`). |
| `cleanupStructuredEncryptionData` | `src/mongo/db/commands/fle2_cleanup.idl` | `cleanupTokens`. |
| `compactStructuredEncryptionData` | `src/mongo/db/commands/fle2_compact.idl` | `compactionTokens`, `encryptionInformation`, `anchorPaddingFactor`, `validator`. |

## Flags and Options to Backport

### Very Easily Doable

- `$bitAnd`, `$bitOr`, `$bitXor`, `$bitNot` expression operators.
- `bulkWrite.errorsOnly` and `bulkWrite.let` if `bulkWrite` has already been implemented.
- `distinct.hint` parser support if not already present.
- Accepting `querySettings` as an internal field and ignoring it in compatibility mode, as long as `setQuerySettings` is not advertised as functioning.

### Needs a Lot of Development

- `$median` and `$percentile`: implementable in aggregation but requires percentile algorithms, accumulator/window integration, serialization, memory limits, and test coverage.
- Query settings with `allowedIndexes` and `reject`: requires query shape hashing, persistent cluster parameter/state storage, validation, planner hooks, command authorization, and explain/debug behavior.
- Search-index command stubs can store metadata in a side collection, but useful behavior needs either Atlas Search/mongot or a substitute search engine.
- Columnstore index catalog parsing and validation can be added, but actual query acceleration requires a columnar index access method and planner support.
- `prepareUnique` for unique conversion requires index validation, writes coordination, and catalog state transitions.

### Very Hard

- `$search`, `$searchMeta`, `$vectorSearch`, and search index commands with real semantics.  The implementation assumes a `mongot` process/protocol and search-specific metadata lifecycle.  A 4.0 backport would either need an external search service integration or should reject these commands.
- Columnstore indexes with real performance semantics.  They require new index key/storage format, projection rules, scan stages, planner costing, and catalog compatibility.
- FLE cleanup/compact real semantics.  Same Queryable Encryption architecture concerns as 6.0/7.0, plus cleanup lifecycle.

### Ignore or Defer

- Sharding-only 8.0 additions such as moveCollection/unshardCollection/changePrimary, range deletion recreation, and transition-to-sharded-cluster commands.
- XRay and FTDC/admin diagnostics unless the compatibility target includes operational tooling, not data APIs.

## 8.0 Compatibility Recommendation

For a 4.0-derived server, do not attempt to make search/vector, columnstore, or Queryable Encryption fully functional in the first compatibility pass.  Add clean command rejections or feature-disabled responses so modern clients fail predictably.  Spend engineering effort on `bulkWrite`, aggregation expressions, write/read flags, and index metadata options that do not require new storage layouts.

## Mongosh Addendum

The sibling `../mongosh` checkout exposes `db.getMongo().bulkWrite()` as an 8.0+ helper backed by Node driver `MongoClient.bulkWrite()`.  This is the client helper that makes the 8.0 client-level/cross-namespace `bulkWrite` command important.  By contrast, `db.collection.bulkWrite()` is marked 3.2+ and calls the driver collection bulk API, which can remain compatible with older servers through ordinary write commands.
