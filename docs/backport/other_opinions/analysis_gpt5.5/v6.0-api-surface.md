# MongoDB 6.0 API Surface and 4.0 Backport Notes

## What Changed From 5.0

6.0 is dominated by Queryable Encryption and deeper time-series/index maturity:

- `create` accepts `encryptedFields` and `changeStreamPreAndPostImages`.
- CRUD commands accept `encryptionInformation` in several paths.
- `compactStructuredEncryptionData` appears as a data-facing command.
- `collMod` is refactored around chained collection options and includes newer time-series/index/pre-image structures.
- `listIndexes` adds `includeIndexBuildInfo`.
- Aggregation adds `$documents`, `$fill`, internal `$densify`, `$queryStats`, `$_internalAllCollectionStats`, and time-series/sharded distribution helpers.
- Expressions add `$dateAdd`, `$dateDiff`, `$dateSubtract`, and `$dateTrunc`.

## Data Command Surface

| Command/API | Source | Additions |
| --- | --- | --- |
| `create` | `src/mongo/db/commands/create.idl` | `changeStreamPreAndPostImages`, `encryptedFields`, still includes `timeseries` and `clusteredIndex`. |
| `find`, `count`, `findAndModify`, writes | query/write IDLs | `encryptionInformation` begins appearing in read/write command shapes. |
| `compactStructuredEncryptionData` | `src/mongo/db/commands/fle2_compact.idl` | Command takes `compactionTokens` and namespace; implementation is FLE2-specific. |
| `listIndexes` | `src/mongo/db/list_indexes.idl` | `includeIndexBuildInfo` in addition to `includeBuildUUIDs`. |
| Aggregation | `src/mongo/db/pipeline/*` | `$documents`, `$fill`, internal densify/bucket and query stats stages. |

## Flags and Options to Backport

### Very Easily Doable

- `$dateAdd`, `$dateDiff`, `$dateSubtract`, `$dateTrunc` as expression operators if the 4.0 expression framework is extended carefully.
- `listIndexes.includeIndexBuildInfo` can be accepted and return empty/default fields when the 4.0 engine has no equivalent.
- `changeStreamPreAndPostImages` and `encryptedFields` can be rejected with clear `CommandNotSupported` or parsed/stored as inert metadata only if clients only inspect catalog metadata.  Inert storage is risky because it advertises semantics that do not exist.
- `$documents` stage is local literal document input and is relatively contained.

### Needs a Lot of Development

- `$fill` and `$densify` require sorted stream semantics and non-trivial pipeline execution but do not require a storage engine rewrite.
- Richer time-series support beyond create-only parsing: writes must be transformed into buckets, queries must unpack buckets, and secondary indexes need translation.
- `changeStreamPreAndPostImages` real semantics require pre-image collection management and change stream integration.

### Very Hard

- Queryable Encryption/FLE2.  `encryptedFields`, `encryptionInformation`, `compactStructuredEncryptionData`, FLE match expressions, ESC/ECOC-style state collections, compaction tokens, and encrypted query planning are coupled.  Backporting only the command names is possible, but usable encrypted range/equality query support is a large architecture project.
- Exact compatibility for time-series update/delete and index behavior.  Later versions depend on bucket catalog code that does not exist in 4.0.

### Ignore or Defer

- Cluster parameter commands, shard split commands, configure collection balancing, moveRange, and other system-level command deltas.
- Query stats command internals unless a client explicitly depends on `$queryStats`.

## Implementation Guidance for a 4.0 Forward-Compatible Server

For 6.0 client compatibility, prioritize:

1. Accept modern command fields with strict validation relaxed behind a compatibility mode.
2. Implement pure aggregation expressions/stages that do not mutate storage.
3. Decide early whether `encryptedFields` should be hard rejected or whether the catalog can preserve it while clearly failing encrypted operations.  Silent acceptance without semantics is dangerous.
