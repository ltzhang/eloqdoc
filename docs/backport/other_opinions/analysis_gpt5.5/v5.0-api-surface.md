# MongoDB 5.0 API Surface and 4.0 Backport Notes

## What Changed From 4.0

5.0 introduces the first major modern command-schema jump visible from 4.0:

- Stable API metadata appears in many IDL command definitions (`api_version: "1"`).
- `hello` exists alongside legacy handshake behavior.
- Many commands are IDL-generated with strict field validation and generated auth checks.
- Index build API includes `commitQuorum` and `setIndexCommitQuorum`.
- Collection creation gains `timeseries`, `clusteredIndex`, and `expireAfterSeconds` at collection level.
- Hidden index helpers appear in the legacy shell (`hideIndex`, `unhideIndex`).
- Aggregation adds `$set`, `$unset`, `$replaceWith`, `$bucket`, `$changeStream`, `$count`, `$merge`, `$planCacheStats`, `$sortByCount`, `$unionWith`, and time-series bucket unpack internals.
- Expressions add `$function`, `$accumulator`, trigonometry, regex expression family, `$convert` and typed conversions, `$date`-adjacent helper coverage, `$round`, trim/replace string operations, `$rand`, `$binarySize`, `$bsonSize`, and `$toHashedIndexKey`.

## Data Command Surface

Public data commands remain the familiar CRUD/DDL/metadata set.  Important 5.0 parser files:

| Command/API | Source | Main request fields or semantic additions |
| --- | --- | --- |
| `find` | `src/mongo/db/query/find_command.idl` | IDL command with `filter`, `projection`, `sort`, `hint`, `collation`, `skip`, `limit`, `batchSize`, `singleBatch`, `allowDiskUse`, `let`, `readConcern`, `runtimeConstants`, and internal resume/UUID fields. |
| `aggregate` | `src/mongo/db/pipeline/aggregate_command.idl` | Adds IDL fields including `pipeline`, `cursor`, `explain`, `allowDiskUse`, `hint`, `let`, `runtimeConstants`, `collectionUUID`, merge/exchange fields. |
| `insert/update/delete` | `src/mongo/db/ops/write_ops.idl` | Adds API Version metadata and replies; update/delete gain top-level `let` and `runtimeConstants`; update entries gain `hint` and pipeline-style `u` parsing. |
| `findAndModify` | `src/mongo/db/ops/write_ops.idl` | IDL parser with `hint`, `let`, `arrayFilters`, `bypassDocumentValidation`, `writeConcern`, and retry statement fields. |
| `create` | `src/mongo/db/commands/create.idl` | Adds `timeseries`, boolean `clusteredIndex`, collection `expireAfterSeconds`, and `recordPreImages`. |
| `createIndexes` | `src/mongo/db/create_indexes.idl` | Adds `hidden`, `wildcardProjection`, `ignoreUnknownIndexOptions`, `commitQuorum`, `isTimeseriesNamespace`. |
| `collMod` | `src/mongo/db/coll_mod.idl` | Can update validator, validation flags, view pipeline, TTL, index options, time-series options, and pre-image flag. |
| `listIndexes` | `src/mongo/db/list_indexes.idl` | Adds `includeBuildUUIDs`, `isTimeseriesNamespace`. |

## Flags and Options to Backport

### Very Easily Doable

- IDL-compatible acceptance of harmless fields: API version metadata, unknown-but-ignored internal fields when a modern client sends them, `comment`, `let` where the execution engine can pass constants into `$expr`.
- Shell helper additions: `hideIndex`, `unhideIndex`, `commitQuorum` argument to `createIndex/createIndexes`.
- Index option parsing for `hidden` if implemented only as planner exclusion metadata.
- `ignoreUnknownIndexOptions` parser behavior.
- Aggregation aliases/stages that are syntactic wrappers: `$set` -> `$addFields`, `$unset` -> projection, `$replaceWith` -> `$replaceRoot`, `$count` -> `$group` + `$project`.
- Expression additions that are pure functions: trigonometry, `$regexFind`, `$regexMatch`, `$replaceOne`, `$replaceAll`, `$trim`/`$ltrim`/`$rtrim`, `$round`, `$isNumber`, `$toBool`, `$toDate`, `$toString`, `$toObjectId`, numeric conversions.

### Needs a Lot of Development

- Wildcard indexes if 4.0 lacks the access method and planner integration in the target baseline.  This requires key generation, catalog validation, planning, multikey behavior, and projection semantics.
- Hidden indexes properly integrated with plan cache invalidation and index selection.
- Pipeline-style updates and update-with-aggregation semantics if the 4.0 baseline lacks the later `UpdateModification` implementation.
- `$unionWith`, `$merge`, and `$out` modern semantics because they touch catalog writes, unique index checks, and write concern behavior.
- `commitQuorum` and two-phase index build semantics if the backport expects exact replica-set behavior.  For standalone or simplified compatibility, it can be parsed and ignored or treated as local completion.
- `let` in find/update/delete/aggregate if constants must be visible across all match and pipeline expression paths.

### Very Hard

- Time-series collections.  The API is a simple `create.timeseries` object, but the implementation is a bucketed collection model with rewritten writes, bucket catalog, min/max metadata, TTL, unpack stage, index rewriting, and later update/delete behavior.  This is architectural, not a parser-only change.
- Clustered collections.  `clusteredIndex` changes the physical identity and ordering contract of records and indexes.  It is not just a catalog flag.
- Stable API strictness/deprecation enforcement for all commands.  This touches the command invocation layer and every command's stability annotations.

### Ignore or Defer

- Resharding, tenant migration, sharding DDL, split/move chunk commands, and test-only commands added in raw command deltas.
- Internal time-series bucket commands if user-facing `timeseries` is not implemented.

## Client Notes

The 5.0 branch still contains the legacy shell.  Compared with 4.0, visible data-helper additions include `hideIndex`, `unhideIndex`, `commitQuorum` parameters for index creation, `hello`, API-strict helper plumbing, and client-side field-level encryption helpers under `src/mongo/shell/keyvault.js`.  Modern `mongosh` is not inside the server repo, but the sibling `../mongosh` checkout adds a current Node-driver-backed client surface; see `mongosh-client-surface.md`.
