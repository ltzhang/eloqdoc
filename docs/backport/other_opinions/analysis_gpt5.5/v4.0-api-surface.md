# MongoDB 4.0 Baseline API Surface

## Parser and Handler Map

The 4.0 branch is the implementation baseline.  It has a mixed parser style:

| API area | Primary 4.0 source | Notes |
| --- | --- | --- |
| CRUD writes | `src/mongo/db/ops/write_ops.idl`, `src/mongo/db/ops/write_ops*` | IDL structs exist for `insert`, `update`, `delete`; no API Version 1 metadata. |
| Queries | `src/mongo/db/commands/find_cmd.cpp`, `getmore_cmd.cpp`, `killcursors_cmd.cpp`, `count_cmd.cpp`, `distinct.cpp` | Mostly hand-written command parsing and canonical query construction. |
| Aggregation | `src/mongo/db/commands/pipeline_command.cpp`, `src/mongo/db/pipeline/*` | `aggregate` command with parser/execution in pipeline subsystem. |
| Collection DDL | `src/mongo/db/commands/create_command.cpp`, `dbcommands.cpp`, `drop_indexes.cpp`, `rename_collection_cmd.cpp` | `create`, `drop`, `collMod`, `convertToCapped`, `renameCollection`, `dropIndexes`. |
| Index creation | `src/mongo/db/commands/create_indexes.cpp`, `src/mongo/db/create_indexes.idl` | `createIndexes` exists; raw IDL command extraction misses it because 4.0 IDL describes a struct, not a command block. |
| Collection metadata | `src/mongo/db/list_collections.idl`, `src/mongo/db/list_indexes.idl`, command cpp files | `listCollections`, `listIndexes`, `collStats`, `dbStats`. |
| Auth/security | `src/mongo/db/auth/action_types.txt`, command-specific `checkAuthForCommand` methods | Action names include CRUD, `createIndex`, `collMod`, `dbStats`, `listIndexes`, etc. |
| Legacy shell client | `src/mongo/shell/collection.js`, `crud_api.js`, `db.js` | The server repo contains the old shell. Modern `mongosh` is in sibling checkout `../mongosh`; see `mongosh-client-surface.md`. |

## Data Commands Accepted by 4.0

The user-facing data API baseline includes:

- Read/query: `find`, `getMore`, `killCursors`, `count`, `distinct`, `aggregate`, `explain`, `mapReduce`, legacy `group`, legacy `geoNear`.
- Write: `insert`, `update`, `delete`, `findAndModify`.
- Collection DDL: `create`, `drop`, `dropDatabase`, `collMod`, `renameCollection`, `convertToCapped`, `cloneCollectionAsCapped`.
- Index DDL and metadata: `createIndexes`, `dropIndexes`, `reIndex`, `listIndexes`, `planCacheSetFilter`, `planCacheListFilters`, `planCacheClearFilters`, `planCacheClear`.
- Metadata/statistics: `listCollections`, `listDatabases`, `collStats`, `dbStats`, `dataSize`, `validate`.

4.0 also accepts many system commands.  For forward compatibility they should be ignored unless a later client unavoidably sends them before using data APIs.

## Command Fields and Flags

### CRUD Writes

`src/mongo/db/ops/write_ops.idl` defines:

- Shared write flags: `bypassDocumentValidation`, `ordered`, `stmtId`, `stmtIds`.
- `insert`: command namespace plus `documents` array, doc sequence capable.
- `update`: `updates` array; each entry has `q`, `u`, `arrayFilters`, `multi`, `upsert`, `collation`.
- `delete`: `deletes` array; each entry has `q`, `limit` mapped to a boolean multi-delete flag, `collation`.

Missing relative to later versions: top-level `let`, `runtimeConstants`, write `hint`, update `sort`, `collectionUUID`, `isTimeseriesNamespace`, `encryptionInformation`, `sampleId`, and bulkWrite command cursor semantics.

### Queries

4.0 query operators include public `$lt`, `$lte`, `$gt`, `$gte`, `$in`, `$nin`, `$ne`, `$exists`, `$type`, `$mod`, `$regex`, `$options`, `$size`, `$elemMatch`, `$all`, `$geoWithin`, `$geoIntersects`, `$near`, `$nearSphere`, and bitwise match operators.  Internal JSON schema predicates are present for schema validation.

Compared with 8.0, 4.0 lacks explicit path-accepting `$eq` in `queryOperatorMap`; equality is still expressible as `{field: value}`.  Later internal FLE and query sampling predicates are absent.

### Indexes

4.0 `NewIndexSpec` supports:

- Required: `key`, `name`.
- Basic options: `background`, `unique`, `partialFilterExpression`, `sparse`, `expireAfterSeconds`, `storageEngine`, `collation`.
- Text options: `weights`, `default_language`, `language_override`, `textIndexVersion`.
- Geo options: `2dsphereIndexVersion`, `bits`, `min`, `max`, `bucketSize`.

Missing relative to later versions: `hidden`, `wildcardProjection`, `commitQuorum`, `ignoreUnknownIndexOptions`, `columnstoreProjection`, `columnstoreCompressor`, `clustered`, `prepareUnique`, `returnOnStart`, `collectionUUID`, and time-series index rewrite awareness.

### Collection Creation

4.0 supports ordinary collection creation, capped collections, validator, validation level/action, collation, views (`viewOn`, `pipeline`), storage engine options, and `_id` index options.  It does not have first-class `timeseries`, `clusteredIndex`, `changeStreamPreAndPostImages`, `recordIdsReplicated`, or `encryptedFields`.

## Aggregation Baseline

Raw extraction found 28 stage registration tokens in 4.0.  Public stages include:

- `$addFields`, `$bucketAuto`, `$collStats`, `$currentOp`, `$facet`, `$geoNear`, `$graphLookup`, `$group`, `$indexStats`, `$limit`, `$listLocalSessions`, `$listSessions`, `$lookup`, `$match`, `$out`, `$project`, `$redact`, `$replaceRoot`, `$sample`, `$skip`, `$sort`, `$unwind`.

Public expression support is broad but pre-5.0: arithmetic, boolean, comparison, array conversion, date part/string conversion, string length/substr/case, set operators, `$map`, `$filter`, `$reduce`, `$let`, `$literal`, `$type`, `$mergeObjects`, and standard accumulators (`$sum`, `$avg`, `$min`, `$max`, `$first`, `$last`, `$push`, `$addToSet`, standard deviations).

Missing later execution families: window functions, `$densify`, `$fill`, `$documents`, `$unionWith`, richer date arithmetic, `$getField`/`$setField`, top/bottom N, percentiles, search/vector stages, and time-series bucket stages.

## Legacy Shell Client Surface

4.0 has `src/mongo/shell`, not modern `mongosh` inside the server tree.  This workspace also has sibling checkout `../mongosh`, analyzed separately in `mongosh-client-surface.md`.

User-facing helper coverage includes `find`, `findOne`, `insert`, `remove`, `update`, `save`, `createIndex`, `createIndexes`, `ensureIndex`, `dropIndex`, `dropIndexes`, `findAndModify`, `validate`, `getIndexes`, `stats`, `dataSize`, `aggregate`, `mapReduce`, `count`, `countDocuments`, `estimatedDocumentCount`, `distinct`, `watch`, `bulkWrite`, and modern CRUD helpers (`insertOne`, `insertMany`, `deleteOne`, `deleteMany`, `replaceOne`, `updateOne`, `updateMany`, findOneAnd*).

Forward compatibility work for the legacy shell is mostly JavaScript wrapper work.  For modern `mongosh`, server command and option compatibility is more important because the shell delegates to the Node driver.
