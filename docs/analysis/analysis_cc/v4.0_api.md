# MongoDB 4.0 — Complete Data-Model & Data-Manipulation API Reference

**Source branch:** `origin/v4.0`  
**Role in this series:** Baseline — all later version documents are deltas against this.  
**Scope:** Data model, indexing, query, aggregation, CRUD, encryption, and auth APIs only.  
Sharding, replication, and transaction internals are excluded unless they directly affect the data API surface.

---

## 1. Index Types

MongoDB 4.0 supports **six** index types, defined in `src/mongo/db/index_names.h`:

| Constant | Wire String | Access Method File |
|---|---|---|
| `INDEX_BTREE` | `""` (empty = default) | `btree_access_method.cpp` |
| `INDEX_2D` | `"2d"` | `2d_access_method.cpp` |
| `INDEX_HAYSTACK` | `"geoHaystack"` | `haystack_access_method.cpp` |
| `INDEX_2DSPHERE` | `"2dsphere"` | `s2_access_method.cpp` |
| `INDEX_TEXT` | `"text"` | `fts_access_method.cpp` |
| `INDEX_HASHED` | `"hashed"` | `hash_access_method.cpp` |

Helper methods on `IndexNames`:
- `findPluginName(BSONObj keyPattern)` — returns the non-btree plugin name from a key pattern object, or `""` for btree.
- `isKnownName(StringData name)` — true if name is one of the six strings above.
- `nameToType(const std::string& accessMethod)` — converts string to `IndexType` enum.
- `existedBefore24(StringData name)` — returns true for 2d, haystack, 2dsphere, text, hashed (only in 4.0; removed in 4.2).

### 1.1 B-Tree Index (default)

Used for all scalar, compound, and multi-key indexes.

**`createIndexes` key pattern format:**
```
{ fieldName: 1 }          // ascending
{ fieldName: -1 }         // descending
{ field1: 1, field2: -1 } // compound
{ "a.b": 1 }              // dotted path (sub-document field)
```

**Per-index options (spec fields):**

| Field | Type | Default | Notes |
|---|---|---|---|
| `key` | object | required | The key pattern |
| `name` | string | required | Unique index name within collection |
| `unique` | bool | false | Enforce uniqueness |
| `sparse` | bool | false | Omit documents lacking the indexed field |
| `background` | bool | false | Build index without holding exclusive lock |
| `expireAfterSeconds` | int | — | Creates a TTL index; field must be a Date |
| `partialFilterExpression` | object | — | Filter predicate; only matching docs are indexed |
| `collation` | Collation | — | Language-specific string comparison |
| `weights` | object | — | Text index only: per-field relevance weights |
| `v` | int | 2 | Index format version; always 2 in 4.0 |
| `storageEngine` | object | — | Engine-specific options |

### 1.2 2D Index

**Key pattern:** `{ fieldName: "2d" }` (one field only, must be first in compound).

**Extra options:**

| Field | Type | Default | Notes |
|---|---|---|---|
| `min` | double | -180 | Lower bound for coordinate values |
| `max` | double | 180 | Upper bound for coordinate values |
| `bits` | int | 26 | Precision of the geohash (1–32) |

**Stored coordinate formats:** legacy coordinate pair `[lon, lat]`, or embedded document `{ x: lon, y: lat }`.

### 1.3 GeoHaystack Index

**Key pattern:** `{ geoField: "geoHaystack", additionalField: 1 }` (geo field must be first).

**Extra options:**

| Field | Type | Default | Notes |
|---|---|---|---|
| `bucketSize` | double | required | Maximum distance between documents in a bucket |

**Note:** As of MongoDB 4.0 this index type is supported but rarely used. It was deprecated in 4.4 and removed from creation in 5.0. It is superseded by 2dsphere.

### 1.4 2DSphere Index

**Key pattern:** `{ geoField: "2dsphere" }` or compound with other fields.

**Extra options:**

| Field | Type | Default | Notes |
|---|---|---|---|
| `2dsphereIndexVersion` | int | 3 | Geometry representation version (2 or 3) |

**Stored geometry formats:** GeoJSON (`Point`, `LineString`, `Polygon`, `MultiPoint`, `MultiLineString`, `MultiPolygon`, `GeometryCollection`) or legacy coordinate pair.

### 1.5 Text Index

**Key pattern:** `{ field: "text" }` or `{ "$**": "text" }` (wildcard text).

**Extra options:**

| Field | Type | Default | Notes |
|---|---|---|---|
| `weights` | object | — | `{ field: weight }` — relative relevance (1–1000) |
| `default_language` | string | `"english"` | Language for stemming and stop words |
| `language_override` | string | `"language"` | Document field that overrides the default language |
| `textIndexVersion` | int | 3 | Text index version |

**Restriction:** Only one text index allowed per collection.

### 1.6 Hashed Index

**Key pattern:** `{ field: "hashed" }` (single field only).

No extra options beyond the common set. Used primarily for range-query-free equality on high-cardinality fields or for even chunk distribution in sharded collections.

## 2. Collection Creation (`create` command)

**Command wire format:**
```js
db.runCommand({
  create: "<collection-name>",
  // options below
})
```

**Options in MongoDB 4.0** (parsed in `src/mongo/db/commands/dbcommands.cpp`):

| Field | Type | Default | Notes |
|---|---|---|---|
| `capped` | bool | false | Create a capped (circular-buffer) collection |
| `size` | int64 | — | Required if `capped: true`; max bytes (must be ≥ 1) |
| `max` | int | — | Optional; max documents in capped collection |
| `autoIndexId` | bool | true | Create an `_id` index automatically |
| `storageEngine` | object | — | Engine-specific collection options |
| `validator` | object | — | JSON Schema or query expression for doc validation |
| `validationLevel` | string | `"strict"` | `"off"` / `"moderate"` / `"strict"` |
| `validationAction` | string | `"error"` | `"error"` / `"warn"` |
| `indexOptionDefaults` | object | — | Default options applied to all new indexes on this collection |
| `viewOn` | string | — | Source collection name (makes this a view) |
| `pipeline` | array | — | Aggregation pipeline for a view |
| `collation` | Collation | — | Default collation for the collection/view |
| `idIndex` | object | — | Explicit spec for the `_id` index |

**Collation object fields:**

| Field | Type | Default | Notes |
|---|---|---|---|
| `locale` | string | required | ICU locale string, e.g. `"en"` |
| `caseLevel` | bool | false | — |
| `caseFirst` | string | `"off"` | `"upper"` / `"lower"` / `"off"` |
| `strength` | int | 3 | 1–5 |
| `numericOrdering` | bool | false | Sort numbers as numbers not strings |
| `alternate` | string | `"non-ignorable"` | `"shifted"` for ignoring punctuation |
| `maxVariable` | string | — | `"punct"` or `"space"` |
| `backwards` | bool | false | Accent sort from end of string |
| `normalization` | bool | false | Unicode normalization |

**Validator / JSON Schema** (added in 3.6): The `validator` field accepts:
- A MongoDB query expression: `{ age: { $gt: 0 } }`
- Or JSON Schema: `{ $jsonSchema: { bsonType: "object", required: ["name"], properties: { ... } } }`

## 3. Index Management Commands

### 3.1 `createIndexes`

```js
db.runCommand({
  createIndexes: "<collection>",
  indexes: [ <indexSpec>, ... ],
  writeConcern: { ... },
  commitQuorum: <string|int>  // v4.4+; not in 4.0
})
```

Each `<indexSpec>` contains the common fields from §1 plus any type-specific fields. Key validation is in `src/mongo/db/commands/create_indexes.cpp` → `parseAndValidateIndexSpecs()`.

**Restrictions in 4.0:**
- `background: true` is supported (asynchronous build).
- Index builds on replica sets: all secondaries apply the build after primary completes.
- No `commitQuorum` parameter (added in 4.4).

### 3.2 `dropIndexes`

```js
db.runCommand({ dropIndexes: "<collection>", index: "<name>" | ["<name>", ...] | { key } | "*" })
```

`"*"` drops all non-`_id` indexes.

### 3.3 `listIndexes`

```js
db.runCommand({ listIndexes: "<collection>", cursor: { batchSize: N } })
```

Returns a cursor of index specification documents.

### 3.4 `reIndex`

Rebuilds all indexes on a collection (rarely needed in 4.0; removed in 6.0).

## 4. Find / Query Command

**Command:** `find`  
**Source:** `src/mongo/db/commands/find_cmd.cpp`

```js
db.runCommand({
  find: "<collection>",
  // fields below
})
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `filter` | object | `{}` | Query predicate |
| `projection` | object | — | Field inclusion/exclusion |
| `sort` | object | — | `{ field: 1/-1 }` |
| `skip` | int | 0 | Documents to skip |
| `limit` | int | 0 | Max docs to return (0 = no limit) |
| `batchSize` | int | 101 | Docs in first batch |
| `singleBatch` | bool | false | Close cursor after first batch |
| `comment` | string | — | Appear in logs/profiler |
| `maxTimeMS` | int | 0 | Server-side timeout in milliseconds |
| `hint` | object\|string | — | Force index; `{ field: 1 }` or index name |
| `readConcern` | object | — | `{ level: "local"\|"majority"\|"linearizable"\|"available" }` |
| `collation` | object | — | Override collection default collation |
| `returnKey` | bool | false | Return only index keys, not full documents |
| `showRecordId` | bool | false | Append `$recordId` to each result document |
| `tailable` | bool | false | Tailable cursor for capped collections |
| `awaitData` | bool | false | Block getMore until data available (for tailable) |
| `noCursorTimeout` | bool | false | Prevent idle cursor expiration (10 min default) |
| `allowPartialResults` | bool | false | Return partial results if a shard is down |
| `oplogReplay` | bool | false | Internal use: optimize oplog queries |
| `max` | object | — | Upper exclusive index bound `{ field: value }` |
| `min` | object | — | Lower inclusive index bound `{ field: value }` |
| `allowDiskUse` | bool | false | Spill to disk for in-memory sorts |

**Note on `allowDiskUse`:** Present in 4.0 for the `find` command when an explicit sort is used; became more prominent in later versions.

### 4.1 Query Operators

Full set of query selectors available in 4.0:

**Comparison:** `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`  
**Logical:** `$and`, `$or`, `$not`, `$nor`  
**Element:** `$exists`, `$type`  
**Evaluation:** `$mod`, `$regex`, `$text`, `$where`, `$expr`  
**Array:** `$all`, `$elemMatch`, `$size`  
**Geospatial:** `$geoWithin`, `$geoIntersects`, `$near`, `$nearSphere`  
**Bitwise:** `$bitsAllClear`, `$bitsAllSet`, `$bitsAnyClear`, `$bitsAnySet`  
**Comment:** `$comment`

## 5. CRUD Commands

### 5.1 `insert`

```js
db.runCommand({
  insert: "<collection>",
  documents: [ <doc>, ... ],
  ordered: true,
  writeConcern: { ... },
  bypassDocumentValidation: false
})
```

| Field | Type | Default |
|---|---|---|
| `ordered` | bool | true — stop on first error |
| `bypassDocumentValidation` | bool | false |
| `writeConcern` | object | — |

### 5.2 `update`

```js
db.runCommand({
  update: "<collection>",
  updates: [{
    q: <filter>,
    u: <update> | <pipeline>,  // pipeline form: v4.2+; not in 4.0
    upsert: false,
    multi: false,
    collation: { ... },
    arrayFilters: [ ... ]
  }],
  ordered: true,
  writeConcern: { ... },
  bypassDocumentValidation: false
})
```

**Update operators in 4.0:**
- **Field:** `$set`, `$unset`, `$inc`, `$mul`, `$rename`, `$setOnInsert`, `$currentDate`
- **Array:** `$push`, `$pull`, `$addToSet`, `$pop`, `$pullAll`, `$`, `$[]`, `$[<identifier>]`
- **Modifiers:** `$each`, `$sort`, `$slice`, `$position` (for `$push`)
- **Bitwise:** `$bit`
- **Isolation:** `$isolated` (removed in 4.0; use transactions instead)

**Note:** Aggregation pipeline form for updates (`u: [<stage>, ...]`) was added in **4.2** — not available in 4.0.

### 5.3 `delete`

```js
db.runCommand({
  delete: "<collection>",
  deletes: [{
    q: <filter>,
    limit: 1,          // 1 = delete one; 0 = delete all matching
    collation: { ... }
  }],
  ordered: true,
  writeConcern: { ... }
})
```

### 5.4 `findAndModify`

```js
db.runCommand({
  findAndModify: "<collection>",
  query: <filter>,
  sort: { ... },
  update: <update>,      // mutually exclusive with remove
  remove: false,
  upsert: false,
  new: false,            // return pre- (false) or post-modification (true) doc
  fields: <projection>,
  bypassDocumentValidation: false,

```

### 5.5 `getMore`

```js
db.runCommand({
  getMore: <cursorId>,
  collection: "<collection>",
  batchSize: <int>,
  maxTimeMS: <int>
})
```

### 5.6 `count` (deprecated)

```js
db.runCommand({
  count: "<collection>",
  query: <filter>,
  limit: <int>,
  skip: <int>,
  hint: <string|object>,
  collation: { ... },
  readConcern: { ... },
  maxTimeMS: <int>
})
```

**Note:** `count` without a predicate may return an inaccurate result (uses collection metadata). Use `$group` + `$sum` in an aggregation pipeline for accurate counts. `countDocuments()` helper wraps `$match` + `$count` aggregation.

### 5.7 `distinct`


## 6. Aggregation Pipeline

**Command:**
```js
db.runCommand({
  aggregate: "<collection>" | 1,  // 1 for db-level
  pipeline: [ <stage>, ... ],
  allowDiskUse: false,
  cursor: { batchSize: <int> },
  maxTimeMS: <int>,
  bypassDocumentValidation: false,
  readConcern: { ... },
  hint: <object|string>,
  comment: <string>,
  collation: { ... },
  explain: <bool>
})
```

### 6.1 Pipeline Stages Available in MongoDB 4.0

#### Data Input / Source
| Stage | Description |
|---|---|
| `$match` | Filters documents by a query predicate |
| `$geoNear` | Outputs documents ordered by proximity to a geospatial point; must be first stage |
| `$indexStats` | Returns index usage statistics for the collection |
| `$collStats` | Returns collection or view statistics (size, count, latency, storage, queryExecStats) |
| `$currentOp` | Returns information about active operations; db-level aggregate only |
| `$listLocalSessions` | Lists sessions in the in-memory session cache; db-level aggregate |
| `$listSessions` | Lists all sessions stored in `system.sessions`; db-level aggregate |
| `$planCacheStats` | Not yet in 4.0 — added in 4.2 |

#### Transformation
| Stage | Description |
|---|---|
| `$project` | Includes, excludes, renames, or computes fields |
| `$addFields` | Adds new fields (equivalent to `$project` that retains all existing fields) |
| `$replaceRoot` | Replaces root document with a specified sub-document or expression |
| `$unwind` | Deconstructs an array field into one document per element |
| `$redact` | Restricts document content using `$$DESCEND`, `$$PRUNE`, `$$KEEP` |

#### Grouping
| Stage | Description |
|---|---|
| `$group` | Groups documents by an expression; computes per-group accumulations |
| `$sortByCount` | Shorthand for `$group` by expression + `$sort` by count |
| `$bucket` | Categorises documents into buckets by an expression |
| `$bucketAuto` | Automatically determines bucket boundaries for N buckets |
| `$facet` | Runs multiple sub-pipelines on the same set of input documents |
| `$count` | Returns a single document with a count of input documents |

#### Sorting and Pagination
| Stage | Description |
|---|---|
| `$sort` | Sorts documents; can use index if first stage or after `$match` |
| `$skip` | Skips N input documents |
| `$limit` | Passes only the first N documents |
| `$sample` | Randomly selects N documents |

#### Joins and Lookups
| Stage | Description |
|---|---|
| `$lookup` | Performs a left outer join to another collection in the same database |
| `$graphLookup` | Recursive join for graph/tree traversal |
| `$unwind` | (also used after `$lookup` to flatten joined arrays) |

#### Output
| Stage | Description |
|---|---|
| `$out` | Writes result to a collection (replaces collection atomically) |

**Note:** `$merge` was added in 4.2; `$out` in 4.0 replaces the entire output collection.

#### Change Streams
| Stage | Description |
|---|---|
| `$changeStream` | Watches for insert/update/replace/delete/invalidate events |

### 6.2 `$group` Accumulators in 4.0

| Accumulator | Description |
|---|---|
| `$sum` | Sums numeric values; non-numeric treated as 0 |
| `$avg` | Averages numeric values |
| `$first` | First value in a group (depends on sort order) |
| `$last` | Last value in a group |
| `$max` | Maximum value |
| `$min` | Minimum value |
| `$push` | Accumulates values into an array |
| `$addToSet` | Accumulates unique values into an array |
| `$stdDevPop` | Population standard deviation |
| `$stdDevSamp` | Sample standard deviation |
| `$mergeObjects` | Merges documents into a single document (added in 3.6) |

### 6.3 `$lookup` Options in 4.0

```js
{ $lookup: {
    from: "<foreign-collection>",
    localField: "<local-field>",
    foreignField: "<foreign-field>",
    as: "<output-array>"
}}
```

OR (pipeline form added in 3.6):
```js
{ $lookup: {
    from: "<foreign-collection>",
    let: { var: "$localField" },
    pipeline: [ ... ],
    as: "<output-array>"
}}
```

Max sub-pipeline depth: 20 levels (constant `kMaxSubPipelineDepth`).

### 6.4 `$changeStream` Options in 4.0

```js
{ $changeStream: {
    fullDocument: "default" | "updateLookup",
    resumeAfter: <resumeToken>,
    startAtOperationTime: <Timestamp>
}}
```

**Change event fields:** `_id` (resume token), `operationType`, `fullDocument`, `ns`, `documentKey`, `updateDescription`, `clusterTime`.

Change streams became GA (Generally Available) in MongoDB 4.0. In 4.0, change streams can be opened on:
- A single collection
- All collections in a database (DB-level aggregate)
- All collections in a deployment (aggregate on `admin` db with collection `1`)

## 8. Text Search

Full-text search via `$text` in `find` or `$match`:
```js
{ $text: {
    $search: "<string>",
    $language: "<lang>",
    $caseSensitive: false,
    $diacriticSensitive: false
}}
```

In aggregation, `$text` can only be used in `$match` as the first stage, and only if a text index exists.

Projection: `{ score: { $meta: "textScore" } }` to get the relevance score.

## 9. Geospatial Commands and Operators

**Query operators:**
- `$near` / `$nearSphere` — finds documents near a point, sorted by distance
- `$geoWithin` — finds documents within a shape
- `$geoIntersects` — finds documents whose geometry intersects a shape

**Aggregation stage:**
- `$geoNear` — pipeline equivalent of `$near`; must be the first stage

**`geoNear` command (standalone command, removed in 4.0 final):** The standalone `geoNear` command was deprecated in 4.0 and removed. Use `$geoNear` aggregation stage instead.

### 10.4 Encryption at Rest

MongoDB 4.0 supports encryption-at-rest via the WiredTiger storage engine encryption:
- Configured via `--enableEncryption` and `--encryptionKeyFile` at server startup
- AES256-CBC or AES256-GCM
- Source: `src/mongo/db/storage/encryption_hooks.cpp`

**Client-Side Field Level Encryption (CSFLE)** was introduced in **4.2** — not available in 4.0.

### 10.5 TLS/SSL Options (connection-level)

Connections can require TLS. The server and client negotiate TLS version, cipher suite, and certificate verification. Configurable via `net.tls.*` settings. Not an index/query API, but affects client connectivity.

## 14. Wire Protocol

MongoDB 4.0 uses `OP_MSG` (introduced in 3.6) as the primary wire protocol for modern drivers. The legacy `OP_QUERY`, `OP_INSERT`, `OP_UPDATE`, `OP_DELETE`, `OP_GET_MORE`, `OP_KILL_CURSORS` opcodes are also supported for backward compatibility.

**OP_MSG structure:** Body (BSON document containing the command) + optional Document Sequences (named arrays of BSON objects, used for `insert`, `update`, `delete`).

**Wire version in 4.0:** minWireVersion=0, maxWireVersion=7.

## 15. Document Validation (JSON Schema)

Supported since 3.6; fully mature in 4.0. The `$jsonSchema` operator in `validator`:

```js
{
  $jsonSchema: {
    bsonType: "object",
    required: ["name", "age"],
    properties: {
      name: { bsonType: "string", description: "must be a string" },
      age:  { bsonType: "int", minimum: 0, maximum: 150 },
      tags: { bsonType: "array", items: { bsonType: "string" } }
    },
    additionalProperties: false
  }
}
```

Supported JSON Schema keywords: `type`/`bsonType`, `enum`, `allOf`, `anyOf`, `oneOf`, `not`, `if`/`then`/`else`, `required`, `properties`, `additionalProperties`, `items`, `maxItems`, `minItems`, `uniqueItems`, `maxLength`, `minLength`, `pattern`, `multipleOf`, `maximum`, `exclusiveMaximum`, `minimum`, `exclusiveMinimum`.

## 16. Feature Compatibility Version (FCV)

```js
db.adminCommand({ setFeatureCompatibilityVersion: "4.0" | "3.6" })
db.adminCommand({ getParameter: 1, featureCompatibilityVersion: 1 })
```

FCV in 4.0 controls which features are active. Setting FCV to "3.6" prevents use of some 4.0-only features (e.g., transactions, SCRAM-SHA-256). This is the mechanism used to safely downgrade.
