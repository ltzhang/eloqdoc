# MongoDB 7.0 API Surface and 4.0 Backport Notes

## What Changed From 6.0

7.0 adds a new cross-namespace write command, optimizer/statistics APIs, richer aggregation, and more encryption/query sampling plumbing:

- `bulkWrite` command appears with `ops`, `nsInfo`, cursor reply, `ordered`, `stmtId(s)`, and `bypassDocumentValidation`.
- `analyze` command appears for collection statistics/histograms.
- `getQueryableEncryptionCountInfo` appears.
- `createIndexes` adds `returnOnStart`.
- `findAndModify`, `count`, and `distinct` gain `sampleId`/`mirrored` style fields used by query sampling/mirroring.
- Aggregation adds public `$densify`, `$setWindowFields`, `$listCatalog`, and internal window support.
- Expressions add `$getField`, `$setField`, `$unsetField`, `$sortArray`, `$firstN`, `$lastN`, `$minN`, `$maxN`, timestamp helpers, and internal FLE expressions.
- Accumulators add `$count`, `$top`, `$topN`, `$bottom`, `$bottomN`, `$firstN`, `$lastN`, `$minN`, `$maxN`.

## Data Command Surface

| Command/API | Source | Request shape |
| --- | --- | --- |
| `bulkWrite` | `src/mongo/db/commands/bulk_write.idl` | `ops`, `nsInfo`, optional `cursor`, `bypassDocumentValidation`, `ordered`, `stmtId`, `stmtIds`, `bypassEmptyTsReplacement`. |
| `analyze` | `src/mongo/db/query/analyze_command.idl` | `key`, `sampleRate`, `sampleSize`, `numberBuckets`. |
| `getQueryableEncryptionCountInfo` | `src/mongo/db/commands/fle2_get_count_info_command.idl` | `tokens`, `queryType`. |
| `createIndexes` | `src/mongo/db/create_indexes.idl` | Adds `returnOnStart`, preserves `commitQuorum`, `collectionUUID`, `isTimeseriesNamespace`. |
| `distinct` | `src/mongo/db/query/distinct_command.idl` | Adds internal sampling/mirroring fields; public `key`, `query`, `collation` remain. |

## Flags and Options to Backport

### Very Easily Doable

- Parser acceptance for `sampleId`, `mirrored`, and other internal sampling flags when ignored on a 4.0-derived standalone.
- `$getField`, `$setField`, `$unsetField`, `$sortArray`, timestamp extraction helpers, and N-value expressions/accumulators, assuming the aggregation expression framework can accept new expression classes.
- `createIndexes.returnOnStart` as a parsed flag that either returns after local start or is rejected when exact two-phase behavior is unavailable.

### Needs a Lot of Development

- `bulkWrite`: feasible without storage architecture changes, but not trivial.  Implement a top-level admin command that maps each `ops` entry to existing insert/update/delete execution on `nsInfo`, enforces ordered/unordered semantics, emits per-op cursor batches, handles write concern and retryable statement ids consistently, and preserves authorization (`find`, `insert`, `update`, `remove`, `bypassDocumentValidation`).
- `$setWindowFields`: large pipeline executor work.  It needs partitioning, sorting, window bounds, memory/spill handling, and all window accumulator variants.
- `$densify` and `$fill`: medium-to-large pipeline stages, especially with partitioning and date unit semantics.
- `analyze`: can be implemented minimally by sampling and returning histogram-like stats, but exact cardinality/histogram compatibility ties into the cost-based optimizer/statistics catalog.

### Very Hard

- Queryable Encryption count info.  It depends on the FLE2 data model and tokenized state collections.
- Full query sampling/analyzer feature set.  It is sharding/telemetry infrastructure more than core storage.
- Global indexes and sharded index catalog commands from raw deltas are sharding architecture and should not be part of a 4.0 data API backport.

### Ignore or Defer

- Dedicated config server transition, historical placement, global index shard commands, write-without-shard-key cluster commands, and other system-level 7.0 deltas.

## Recommended 7.0 Backport Order

1. Implement aggregation expression/accumulator additions that are pure functions.
2. Add `bulkWrite` as a compatibility command using existing write paths.
3. Add `$densify`/`$fill` only after expression work is stable.
4. Treat `analyze` as optional unless the client workload explicitly calls it.
